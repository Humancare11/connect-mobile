### Purpose of the app

Based on the screens and services, this is a **patient-facing telehealth / healthcare-portal companion app** for the "Humancare Connect" platform. It lets a patient:

## 4. Backend / Server Details

### Base URL / environments

There is **only one environment** — production. `lib/config/api_config.dart`:

- Reads `API_BASE_URL` → falls back to `VITE_API_URL` → falls back to `BACKEND_URL` → falls back to a hardcoded default: `https://humancareconnect.co/api`.
- Normalizes the URL to always end in `/api`.

No dev/staging URL switch exists in code. ⚠️ Not confirmed from code – check with the team if a staging backend exists and how it would be targeted (likely just a different local `.env`).

### Backend type

**REST API** (JSON over HTTPS) plus a **Socket.IO** channel for real-time signaling (appointment rooms / video call events). No GraphQL, no direct Firebase Firestore/Realtime Database usage, no Supabase.

### Networking library, interceptors, error handling

- Built on the plain `http` package, wrapped in a custom `lib/services/api_client.dart` (`ApiClient`) exposing `get`/`post`/`put`/`patch`.
- Every request:
  - Attaches `Authorization: Bearer <token>` from `TokenStorageService` if present.
  - Has a 30-second timeout (15s for the token-refresh call).
  - Logs request/response in debug builds only, with tokens/passwords/OTP/secrets redacted (`_redactSecrets`).
  - Registers "activity" with `IdleSessionTimer` (resets the inactivity/auto-logout clock) and toggles the global `LoadingService` overlay (unless called with `silent: true`).
- **401 handling / token refresh (built-in "interceptor" behavior):** On a 401 from a request that *did* carry a token, `ApiClient` automatically calls `POST /auth/refresh` (coalesced — concurrent 401s share a single in-flight refresh so the refresh token isn't raced), retries the original request once with the new token, and if that still fails, clears all stored tokens and triggers `SessionExpiredService` (a global "please log in again" gate). A 401 from a request with no token (e.g. failed login) is treated as a normal auth failure, not a dead session.
- Errors are mapped to user-friendly messages by exception type (`SocketException`, `TimeoutException`, `HandshakeException`/`TlsException`, `http.ClientException`, including a web-specific CORS message).

## 5. Authentication

### Login methods

- **Email + password** (`AuthService.login`).
- **Google Sign-In** (`google_sign_in` package, OAuth), including a first-time "complete your profile" registration step for new Google users.
- **OTP-based registration** (`sendRegisterOtp` + `register`) and **OTP-based password reset** (`sendForgotOtp` + `verifyForgotOtp` + `resetPassword`).
- **Email-change verification** deliberately *reuses* the forgot-password OTP endpoints (no dedicated backend endpoint exists for this) — documented in code comments in `auth_service.dart`.
- No Apple Sign-In found in dependencies or code.

### Auth mechanism

**Custom JWT-style bearer tokens** issued by the backend (not Firebase Auth). `AuthService` looks for the token under many possible response keys (`token`, `accessToken`, `access_token`, `jwt`, etc.) for backend-response tolerance. Google Sign-In produces an access token that is exchanged with the backend at `POST /auth/google`, which returns the app's own bearer token — Firebase Auth itself is not used for identity.

### Where the token is stored

- **Mobile (Android/iOS):** `flutter_secure_storage` (encrypted keystore/keychain-backed) — chosen explicitly because this is a health-record app and plain `SharedPreferences` on Android is unencrypted XML that also rides along in default app-data backups (see code comment in `token_storage_service.dart`).
- **Web:** `shared_preferences` (documented as a deliberate scope decision — web wasn't part of the security hardening pass and isn't in scope for the Play Store release).
- A lazy, per-field **migration path** exists: on mobile, if a value isn't yet in secure storage, it's read from the legacy `SharedPreferences` location, copied into secure storage, and the old copy deleted — so existing logged-in users aren't logged out by the migration.

### Token refresh and logout flow

- **Refresh:** handled transparently inside `ApiClient` on any 401 (see [Section 4](#4-backend--server-details)) via `POST /auth/refresh`, sending the refresh token as the bearer credential plus an `X-Auth-Role` header. Refreshes are coalesced across concurrent requests.
- **Logout / session death** happens via `TokenStorageService.clearAll()`, called from three paths, all funneling to the same place:
  1. Manual "Log Out" (Account screen).
  2. `SessionExpiredService` triggered by a failed refresh / repeated 401 (global gate shown via `SessionExpiredGate` wrapping the whole app in `main.dart`).
  3. `IdleSessionTimer` — a **30-minute inactivity auto-logout** timer, reset on every API call and (per `IdleActivityListener`) on user taps/scrolls anywhere in the app.
- Logout also best-effort signs the user out of native Google Sign-In so a shared device shows a fresh account picker next time.

### Navigation

Plain `Navigator` (`MaterialApp.routes` for the 3 booking steps, `Navigator.push` elsewhere). `MainScreen` keeps all 5 tabs alive via `IndexedStack`-style lazy-built pages so switching tabs doesn't lose scroll/search state, and exposes a static `switchToTab()` so `NotificationService` can jump tabs on an already-mounted screen when a push notification is tapped.

### Complex business logic worth understanding first

- **`lib/services/api_client.dart`** — token refresh coalescing and global session-expiry detection (see [Section 5](#5-authentication)). Read this before touching any networking code.
- **`lib/controllers/video_call_controller.dart`** — WebRTC signaling/call lifecycle. Explicitly ported 1:1 from the web app's `VideoCall.jsx` for behavioral parity (perfect-negotiation pattern, ICE restart, foreground-service keep-alive on Android). The code comments note the app only ever authenticates as a patient, so the "is this the doctor" branches are always `false` at runtime but are kept for parity with the shared signaling protocol.
- **`lib/services/token_storage_service.dart`** — the lazy per-field migration from `SharedPreferences` to `flutter_secure_storage`.
- **`lib/services/idle_session_timer.dart`** + **`lib/widgets/idle_activity_listener.dart`** — 30-minute inactivity auto-logout.
- **`lib/services/loading_service.dart`** — counter-based (not boolean) global loading overlay, with a minimum-visible-duration to avoid flicker.
